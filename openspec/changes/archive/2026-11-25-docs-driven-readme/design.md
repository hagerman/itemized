# Design

## Context

See `proposal.md` for motivation. Today, `web/scripts/docs/build.ts` parses every Markdown file under `docs/` via `loadDocs()` in `web/scripts/docs/lib.ts` and emits two outputs:
1. The standalone static documentation website under `dist/docs-site/` (not committed).
2. The offline in-app Help bundle under `web/src/generated/help/` (committed and staleness-checked by `web/scripts/docs/check.ts`).

Meanwhile, `docs/assets/*.png` contains 12 automated, high-DPI, demo-banner-free screenshots generated by `web/scripts/docs/screenshots.ts` (`make docs-screenshots`). Root `README.md` is still hand-maintained and references `docs/screenshot-inventory.jpg`, duplicating content already owned by `docs/`.

## Goals / Non-Goals

**Goals:**
- Generate `README.md` deterministically from parsed `docs/` files in `make docs-build` (`npm run docs:build`).
- Replace `docs/screenshot-inventory.jpg` with curated automated screenshots from `docs/assets/` (hero + workflow gallery) and delete `docs/screenshot-inventory.jpg`.
- Enforce `README.md` freshness, image/link integrity, and brand capitalization in `make docs-check` (`npm run docs:check`).
- Keep `README.md` readable, scannable, and GitHub-rendered cleanly without raw front matter or broken relative paths.

**Non-Goals:**
- Changing the static docs website layout or the in-app Help bundle.
- Capturing new screenshots beyond the existing `docs/assets/*.png` set produced by `web/scripts/docs/screenshots.ts`.
- Converting `README.md` into an exhaustive copy of every page under `docs/`; it remains a concise entry point that extracts canonical snippets/tables and links into `docs/` for deep dives.

## Decisions

### 1. Dedicated README generator module (`web/scripts/docs/readme.ts`) invoked by `buildAllDocs()`
- **Decision**: Add `generateReadmeContent(docs: ParsedDoc[], root: string): string` in `web/scripts/docs/readme.ts`, called by `buildAllDocs()` in `web/scripts/docs/build.ts` to write `<root>/README.md`, and called by `checkDocs()` in `web/scripts/docs/check.ts` when `checkStaleness` is enabled.
- **Rationale**: Mirrors the exact pattern already used for `generateHelpFilesContent()` and `web/src/generated/help/`, keeping generation pure/deterministic and easy to unit-test against temp directories in `web/src/docs-check.test.ts`.
- **Alternatives considered**:
  - *In-place marker replacement (`<!-- BEGIN/END -->`)*: Allows partial hand edits outside markers, but risks drift in prose/screenshots outside markers and complicates staleness checks. Full generation from a clean template + `docs/` extraction is simpler and guarantees zero drift.
  - *Separate `make readme-build` target*: Easy to forget; integrating into `make docs-build` and `make docs-check` ensures every contributor and CI run keeps `README.md` in sync automatically.

### 2. Extracting canonical content from `docs/`
- **Decision**: Extract structured data directly from `ParsedDoc` objects loaded by `loadDocs()`:
  - **Header & Navigation**: Logo (`web/public/icon-192.png`), lowercase `itemized` heading, tagline, live demo link (`https://demo.itemizedapp.com`), and top-level doc links (`docs/get-started/getting-started.md`, `docs/self-hosting/README.md`, `docs/api.md`, `CONTRIBUTING.md`).
  - **Hero Screenshot**: `docs/assets/inventory.png` (using the alt text from `docs/get-started/getting-started.md`).
  - **Curated Screenshot Gallery**: A clean HTML 2-column table of screenshots picked from `docs/assets/` with captions linking to the corresponding `docs/` guides:
    - `docs/assets/scanner.png` → [Barcode & QR Scanning](docs/use/barcode-scanning.md)
    - `docs/assets/shopping-list.png` → [Automatic Shopping List](docs/use/shopping-list.md)
    - `docs/assets/product-detail.png` → [Inventory & Expiration Rules](docs/use/inventory-and-expiration.md)
    - `docs/assets/settings-printers.png` → [Direct Zebra ZPL Label Printing](docs/use/label-printing.md)
    - `docs/assets/search.png` → [Instant Search & Shortcuts](docs/use/search-and-shortcuts.md)
    - `docs/assets/mobile-pwa.png` → [Mobile PWA](docs/get-started/install-pwa.md) (styled with constrained width/height so portrait mobile fits nicely alongside desktop captures, or placed in a dedicated centered mobile callout).
  - **What itemized does / Feature Guide**: Generated from `docs/` `use` and `get-started` pages (`frontMatter.title`, `frontMatter.summary`, and relative link `docs/<relPath>`), ordered by `frontMatter.order`.
  - **Quick Start**: Extract the YAML `compose.yaml` fenced block from `docs/self-hosting/docker-compose.md` and the `docker run` fenced block from `docs/self-hosting/docker-run.md`, plus the platform install table from `docs/self-hosting/README.md` (with relative links rewritten from `self-hosting/` to `docs/self-hosting/`).
  - **HTTPS & Reverse Proxy**: Concise summary derived from `docs/self-hosting/README.md#3-reverse-proxy-and-tls` with a direct link to the Caddy/nginx/Traefik configs.
  - **Configuration**: Extract the Markdown environment variable table verbatim from `docs/self-hosting/configuration.md` and rewrite its relative links (`README.md#...` → `docs/self-hosting/README.md#...`, `../use/...` → `docs/use/...`, `../get-started/...` → `docs/get-started/...`). Because `internal/docsverify` already verifies `docs/self-hosting/configuration.md` against Go code, `README.md` automatically inherits that verification.
  - **Development, Security, and License**: Concise commands aligned with `Makefile` (`make check`, `make build`, `make docs-build`, local demo mode, Docker build), plus links to `CONTRIBUTING.md`, `SECURITY.md`, and `LICENSE` (GNU Affero General Public License v3.0).

### 3. Validation in `web/scripts/docs/check.ts`
- **Decision**: Extend `checkDocs()` with:
  1. **README staleness check** (under `checkStaleness`): Compare `<root>/README.md` against `generateReadmeContent(docs, root)` when the required source docs exist; fail with an actionable `run 'make docs-build'` message on mismatch.
  2. **README image & link verification**: Parse `<img src="..." alt="...">` and Markdown `![alt](src)` / `[text](href)` in `README.md` to confirm non-empty alt text, existing local image files, and valid relative file/doc links (including heading anchors into `docs/`).
  3. **README brand capitalization check**: Reuse the same non-sentence-start `"Itemized"` regex check already applied to `docs/`.
- **Rationale**: Ensures `README.md` meets the same quality bar as `docs/` and catches any broken asset or stale edit in CI.

## Risks / Trade-offs

- **[Extraction fragility if headings/fences in `docs/self-hosting/*.md` change]** → Keep extraction focused on stable Markdown structures (first `yaml` fence in `docker-compose.md`, first `bash` fence in `docker-run.md`, the Markdown table in `configuration.md`, and the platform table in `self-hosting/README.md`) and fail loudly with a clear error message if an expected block is missing.
- **[Portrait `mobile-pwa.png` aspect ratio vs. landscape desktop screenshots]** → Render the desktop screenshots in a balanced 2×2 or 2-column grid (e.g., `scanner.png`, `shopping-list.png`, `product-detail.png`, `settings-printers.png`) and present `mobile-pwa.png` cleanly (e.g., constrained height or a dedicated centered mobile callout) so GitHub's README rendering looks crisp and well-proportioned.
- **[Temp project fixtures in `web/src/docs-check.test.ts` do not have full `self-hosting/*.md` files]** → Gate README staleness checks cleanly on `checkStaleness` (which existing unit tests already set to `false`) and add dedicated unit tests in `web/src/docs-check.test.ts` that test `generateReadmeContent` and README validation with complete fixtures.
